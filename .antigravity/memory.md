# 🧠 Память проекта Warehouse (Antigravity Core Memory)

## Краткое описание
**Warehouse Management System** — система управления складом на базе **FastAPI** + **Firebase Firestore**. 
Поддерживает десктопную (админ/кладовщик) и мобильную (сотрудники) версии интерфейса.
Склад: «Бестужевская 10».

---

## ⚡ Быстрые команды

```bash
# Запуск сервера (из корня проекта)
python run_warehouse.py

# Запуск мобильного сервера разработчика
```

API документация (Swagger): http://localhost:8000/docs

Дашборд (React SPA): http://localhost:8000/desktop/dashboard

## 💡 Правила оптимизации токенов и работы ИИ-ассистента

### 1. 🔍 Умный поиск и частичное чтение кода (Token Saver)
* **Никогда не читать файлы целиком без необходимости.** Чтение файлов крупного размера тратит недельный лимит API впустую.
* **Использовать гибкий поиск:** Сначала запускать `grep_search` с флагом `MatchPerLine: true` для поиска конкретных вхождений (функций, маршрутов, переменных).
* **Считывать только нужные диапазоны строк:** При использовании `view_file` обязательно передавать параметры `StartLine` и `EndLine`, ограничивая область просмотра целевой функцией или логическим блоком.
* **Понимание структуры без чтения кода:** Сначала проверять карту проекта `project_map.txt` или дерево файлов в `memory.md`, и только потом открывать конкретный фрагмент кода.

### 2. 🚫 Запрет на использование браузерного агента (No Browser / No Tester)
* **Никогда не запускать браузерного агента (`browser_subagent`) и не пытаться управлять экраном.**
* Для выполнения и тестирования задач использовать исключительно терминал (`run_command`), просмотр файлов и другие текстовые инструменты. Никакого визуального тестирования через браузер.

### 3. 🇷🇺 Общение и планирование на русском языке
* **Всегда писать ответы, планы реализации (`implementation_plan.md`) и отчеты (`walkthrough.md`) на русском языке.**
* **План реализации должен быть сформирован до начала выполнения процесса изменений (в фазе планирования) строго на русском языке.**

## 🛠 Раздел навыков разработки (Skills)

### 🎯 Навык 1: Безопасное взаимодействие с Firestore REST API
Используется при необходимости извлечь или изменить данные в Firebase.
1. **Использовать OAuth2:** Всегда использовать Bearer токен через `auth_service.py` или `warehouse_service.py`. Не делать запросы напрямую с API-ключом (он не авторизован для Firestore REST).
2. **Использовать кэширование:** При чтении проверять кэш (`_cache` или `_user_cache`).
3. **Обработка Quota Exceeded:** При HTTP 429 возвращать понятную ошибку на русском языке: `"Превышена квота запросов к Firebase Spark. Пожалуйста, подождите 5-10 минут."`

### 🎯 Навык 2: Работа с Local-First Синхронизацией (Push/Pull)
Используется при обновлении каталога товаров или синхронизации офлайн-операций.
1. **Мягкое удаление (Soft Delete):** Никогда не удалять записи из `warehouse_items` физически. Выставлять `isDeleted = True` и обновлять временную метку `updatedAt`.
2. **Дельта-синхронизация (Pull):** Метод `pull_items_changes(last_pulled_at)` должен возвращать только измененные товары (у которых `updatedAt > last_pulled_at`).
3. **Пакетная обработка офлайн-действий (Push):** Офлайн-действия приходят в виде списка `SyncPushOperation`. Обрабатывать их последовательно, возвращая детальный отчёт об успехах/ошибках.

### 🎯 Навык 3: Добавление новых API эндпоинтов в FastAPI
Используется при расширении функционала склада или добавлении интеграций.
1. **Регистрация роута:** Добавлять роуты в [app/main.py](file:///c:/Users/pankr/PycharmProjects/Warehouse/app/main.py).
2. **Валидация:** Создавать Pydantic-модели в [app/models.py](file:///c:/Users/pankr/PycharmProjects/Warehouse/app/models.py) для входных данных.
3. **Валидация сессии:** Запросы, изменяющие остатки (списания, поступления), должны проходить валидацию сессии через `_validate_user_from_request`.
4. **Сброс кэша:** После любой мутации (POST/PUT/DELETE) сбрасывать кэш дашборда: `_dashboard_cache.clear()`.

### 🎯 Навык 4: Внесение изменений во фронтенд (Jinja2 + React)
Используется при доработке или создании десктопных страниц.
1. **Наследование Jinja2:** Все десктопные шаблоны должны наследоваться от `base/desktop_base.html`.
2. **Стилизация:** Использовать чистый CSS. Подключать стили через статические файлы, стилизовать аккуратно и в единой цветовой гамме (светлая/тёмная тема, скругления, тени).
3. **Навигация:** Убедиться, что navbar подсвечивает текущий открытый пункт (через React router в SPA или `active_page` в Jinja2).

### 🎯 Навык 5: Диагностика и Отладка системы
Используется при возникновении сбоев авторизации или рассинхронизации данных.
1. Запустить сервер в фоновом режиме: `python run_warehouse.py` (автоматически активирует `.venv`).
2. Запустить `test_firebase.py` для тестирования обмена токенами и проверки доступа.
3. Запустить `check_users.py` для вывода списка пользователей непосредственно из Firestore.
4. Проверить консоль на наличие ошибок `401 Unauthorized` или `403 Forbidden`.

### 🎯 Навык 6: Работа с медиаресурсами и изображениями товаров
Используется при выводе фото в списках товаров, карточках деталей, списаниях и профилях.
1. **Без внешних плейсхолдеров**: Не прописывать в коде ссылки на внешние сервисы вроде `via.placeholder.com` (не работают в оффлайне).
2. **Локальный оффлайн-резерв**: Для товаров без фото выводить Phosphor-иконку коробки `<i class="ph ph-package"></i>` внутри контейнера со стилями.
3. **Фильтрация плейсхолдеров**: В JavaScript и шаблонах Jinja2 всегда отсекать пустые адреса и ссылки со словом `placeholder`.
4. **Инициалы вместо аватаров**: Если у пользователя нет фото, рендерить первый символ его имени в верхнем регистре.

## 🔐 Аутентификация

### Механизм авторизации:
1. **Firebase Admin SDK** через сервисный аккаунт (`firebase/firebase_credentials.json`).
2. **OAuth2 токен** с кэшированием (токен живёт ~1 час, кэшируется на 3000 сек).
3. **Кэширование пользователей** (`UserCache` с TTL):
   - Данные пользователя: 120 сек.
   - Состояние аутентификации: 30 сек.
   - Уменьшено количество запросов к Firestore.

### Важно:
* При перезапусках сервера (`uvicorn` hot-reload) сессии мобильных пользователей автоматически считываются из Firestore по их `user_id` и восстанавливаются во избежание вылетов (ошибки 403).
* `_get_bearer_token` имеет встроенный цикл повторных попыток (до 3 раз с задержкой 1 сек) для обхода сбоев сети Google APIs при включенном VPN.

### Аутентификация (auth router `/api/auth`)
| Метод | Путь | Описание |
|-------|------|----------|
| POST | `/api/auth/login?username=&password=` | Вход |
| POST | `/api/auth/logout` | Выход |
| GET | `/api/auth/state?user_id=` | Состояние пользователя |
| GET | `/api/auth/me` | Текущий пользователь |
| POST | `/api/auth/shift/start?user_id=` | Начать смену |
| POST | `/api/auth/shift/end?user_id=` | Закончить смену |
| GET | `/api/auth/health` | Health check |

| Метод | Путь | Описание |
|-------|------|----------|
| GET | `/api/warehouse/items` | Все товары |
